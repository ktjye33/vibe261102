# PRD: 오늘의 할일 (Today's Todo) 웹페이지

- 문서 버전: v0.2 (설계 단계 — 열린 질문 결정 반영)
- 작성일: 2026-11-02
- 상태: Draft — 구현 전 설계 문서

---

## 1. 개요

### 1.1 배경
하루 단위로 해야 할 일을 빠르게 적고, 체크하고, 정리할 수 있는 가벼운 웹페이지가 필요하다. 복잡한 프로젝트 관리 도구가 아니라 "오늘"에 집중하는 단순한 도구를 목표로 한다.

### 1.2 목표
- 오늘 할 일을 3초 안에 추가할 수 있다.
- 완료/미완료 상태를 한눈에 파악할 수 있다.
- 새로고침하거나 브라우저를 닫았다 열어도 데이터가 유지된다.
- 별도 설치·로그인 없이 브라우저에서 바로 사용한다.

### 1.3 비목표 (Out of Scope, v1)
- 회원가입/로그인, 다중 기기 동기화
- 팀 공유·협업 기능
- 반복 일정, 캘린더 연동, 알림(푸시)
- 서버/데이터베이스 구축

## 2. 대상 사용자

| 페르소나 | 설명 | 핵심 니즈 |
|---|---|---|
| 직장인 | 출근 후 오늘 업무를 정리 | 빠른 입력, 우선순위 표시 |
| 학생 | 과제·공부 계획 관리 | 진행률 확인으로 동기 부여 |
| 개인 사용자 | 장보기·집안일 등 일상 관리 | 단순함, 모바일 사용성 |

---

## 3. 사용자 스토리

1. 사용자로서, 할 일을 입력하고 Enter를 눌러 바로 추가하고 싶다.
2. 사용자로서, 할 일을 클릭(체크)해 완료 처리하고 다시 되돌리고 싶다.
3. 사용자로서, 잘못 적은 할 일을 수정하거나 삭제하고 싶다.
4. 사용자로서, 오늘 몇 개를 끝냈는지 진행률로 보고 싶다.
5. 사용자로서, 전체/진행 중/완료 항목을 필터링해 보고 싶다.
6. 사용자로서, 중요한 일에 우선순위를 표시하고 싶다.
7. 사용자로서, 완료된 항목을 한 번에 정리하고 싶다.
8. 사용자로서, 날짜가 바뀌면 어제 끝내지 못한 일을 오늘로 가져오고 싶다.

## 4. 기능 요구사항

### 4.1 필수 기능 (P0 — MVP)

| ID | 기능 | 상세 | 수용 기준 |
|---|---|---|---|
| F-01 | 오늘 날짜 표시 | 상단에 `2026년 11월 2일 (월)` 형식으로 표시 | 페이지 로드 시 로컬 시간 기준 날짜가 보인다 |
| F-02 | 할 일 추가 | 입력창 + 추가 버튼, Enter 키 지원 | 빈 문자열·공백만 입력 시 추가되지 않음. 최대 100자 |
| F-03 | 완료 토글 | 체크박스 클릭 시 완료/미완료 전환 | 완료 항목은 취소선 + 흐린 색으로 표시 |
| F-04 | 할 일 수정 | 텍스트 더블클릭(모바일: 수정 버튼) 시 인라인 편집 | Enter 저장, Esc 취소, 빈 값 저장 시 원래 값 유지 |
| F-05 | 할 일 삭제 | 각 항목의 삭제(×) 버튼 | 클릭 즉시 삭제, 목록에서 제거 |
| F-06 | 데이터 유지 | `localStorage`에 저장 | 새로고침 후에도 목록·상태가 동일 |
| F-07 | 진행률 | `3 / 5 완료 (60%)` + 진행 바 | 추가·토글·삭제 시 즉시 갱신 |
| F-08 | 빈 상태 안내 | 할 일이 없을 때 안내 문구 | "오늘 할 일을 추가해보세요" 표시 |
| F-09 | 우선순위 | 높음·보통·낮음 3단계. 추가 시 선택(기본값 보통), 항목에서 클릭해 변경. 색상 라벨로 표시 | 목록은 미완료 → 완료 순, 그 안에서 높음 → 보통 → 낮음, 같은 우선순위는 추가한 순서로 정렬된다 |
| F-10 | 기록 영구 보관 | 지난 날짜의 할 일(완료·미완료 모두)을 삭제하지 않고 계속 보관 | 날짜가 바뀌어도 이전 항목이 저장소에 그대로 남는다. 자동 삭제 없음 |

### 4.2 권장 기능 (P1)

| ID | 기능 | 상세 |
|---|---|---|
| F-11 | 필터 | 전체 / 진행 중 / 완료 탭 |
| F-12 | 미완료 항목 이월 (매번 확인) | 날짜가 바뀐 뒤 첫 접속 시, 직전 날짜의 미완료 항목이 있으면 **매번** 확인 창을 띄운다. 상세 흐름은 4.4 참고 |
| F-13 | 다크 모드 | 시스템 설정(`prefers-color-scheme`) 따름 + 수동 토글 |
| F-14 | 완료 항목 일괄 삭제 | "완료 항목 지우기" 버튼, 확인 후 실행. **오늘 날짜의 완료 항목만** 삭제하며 지난 날짜 기록에는 영향 없음 |
| F-15 | 지난 기록 보기 | 날짜 이동(◀ 오늘 ▶) 또는 날짜 선택으로 과거 날짜의 할 일과 완료율을 읽기 전용으로 확인 |

### 4.3 선택 기능 (P2)

| ID | 기능 | 상세 |
|---|---|---|
| F-16 | 직접 정렬 (드래그 앤 드롭) | 정렬 방식을 "우선순위순 / 직접 정렬" 중 선택. 직접 정렬로 바꾸면 그때 보이던 우선순위 순서에서 시작하고, 미완료 항목 왼쪽의 손잡이(⠿)를 끌어 순서를 바꾼다. 마우스·터치 모두 지원, 손잡이에 포커스 후 ↑/↓ 키로도 이동. 완료 항목은 항상 아래 |
| F-17 | 예상 소요 시간 | 추가·수정 시 10분 ~ 4시간 중 선택(선택 안 해도 됨). 항목 아래에 `⏱ 30분` 표시. 진행률 아래에 `예상 시간 총 2시간 · 남은 1시간 30분` 합계 표시 |
| F-18 | 백업 내보내기 / 가져오기 | 전체 기록을 `todolist-backup-YYYY-MM-DD.json`으로 저장. 가져오기는 기존 기록과 **합치며**, 같은 id는 백업 내용으로 바뀐다. 실행 전 개수를 보여주고 확인 |
| F-19 | 기간별 통계 | 헤더의 📊 버튼으로 통계 창을 연다. 최근 7일 / 30일 선택. 완료율·완료 개수·하루 평균·기록한 날·완료한 예상 시간을 요약하고, 날짜별 완료율 막대그래프(마우스를 올리면 수치 표시, 누르면 그 날짜로 이동)와 표 보기를 제공 |

### 4.4 미완료 항목 이월 흐름 (F-12)

1. 페이지 로드 또는 탭 복귀 시 `lastDate`와 오늘 날짜를 비교한다.
2. 다르면 `lastDate` 날짜의 미완료 항목을 찾는다. 없으면 `lastDate`만 오늘로 갱신하고 끝낸다.
3. 있으면 확인 창을 띄운다.
   ```
   ┌──────────────────────────────────┐
   │ 어제 못 끝낸 일이 3개 있어요.      │
   │ 오늘 할 일로 가져올까요?           │
   │                                  │
   │ ☑ ● 보고서 초안 작성              │
   │ ☑ ● 팀 회의 준비                  │
   │ ☑ ● 책 반납                       │
   │                                  │
   │        [건너뛰기]  [가져오기]      │
   └──────────────────────────────────┘
   ```
   - 모든 항목이 기본 선택. 사용자가 항목별로 선택 해제 가능.
   - 우선순위 색상 라벨을 함께 표시.
4. **가져오기:** 선택한 항목마다 오늘 날짜로 새 항목을 만든다(텍스트·우선순위 복사, `carriedFrom`에 원본 id 기록). 원본은 지난 날짜에 미완료 상태로 그대로 남아 기록이 보존된다.
5. **건너뛰기:** 아무것도 가져오지 않는다. 원본은 지난 날짜에 미완료로 남는다.
6. 어느 쪽이든 `lastDate`를 오늘로 갱신한다. 같은 날 다시 묻지 않는다.
7. 며칠 만에 접속한 경우에도 **직전 접속일(`lastDate`)의 미완료 항목만** 대상으로 한다. 문구는 "어제" 대신 "11월 1일(토)에"처럼 실제 날짜로 표시한다.

- 터치 타깃 최소 44×44px

- 우선순위 색상: 높음 = 빨강 계열, 보통 = 주황 계열, 낮음 = 회색 계열

## 6. 데이터 설계

### 6.1 Todo 항목 모델

```ts
type Priority = 'high' | 'medium' | 'low';

interface Todo {
  id: string;          // crypto.randomUUID()
  text: string;        // 1~100자
  completed: boolean;
  priority: Priority;  // 기본값 'medium'
  date: string;        // 'YYYY-MM-DD' (로컬 기준, 해당 할 일의 날짜)
  createdAt: number;   // epoch ms
  completedAt?: number;
  carriedFrom?: string; // 이월로 생성된 경우 원본 Todo의 id
  estimate?: number;    // 예상 소요 시간(분): 10, 15, 30, 45, 60, 90, 120, 180, 240
  order?: number;       // 직접 정렬 순서(같은 날짜 안에서 작은 값이 위)
}
```

### 6.1.1 백업 파일 형식

```json
{
  "app": "todolist",
  "version": 1,
  "exportedAt": "2026-11-02T09:00:00.000Z",
  "todos": [ /* Todo[] */ ]
}
```
- 가져오기는 `todos` 배열(또는 최상위가 배열인 파일)을 읽고, 형식이 맞지 않는 항목은 제외한다.
- 저장된 데이터가 손상돼 저장을 멈춘 상태에서 백업을 가져오면 저장을 다시 켠다(복구 경로).

### 6.2 저장 구조 (localStorage)

| Key | 값 | 설명 |
|---|---|---|
| `todolist:v1:todos` | `Todo[]` (JSON) | 전체 할 일 목록 (지난 날짜 포함, 영구 보관) |
| `todolist:v1:lastDate` | `'YYYY-MM-DD'` | 마지막 접속 날짜 (이월 판단용) |
| `todolist:v1:settings` | `{ theme, filter, sort }` | 테마·필터·정렬 방식(`priority` / `manual`) |

- 키에 버전(`v1`)을 포함해 향후 스키마 변경 시 마이그레이션 가능하게 한다.
- 모든 읽기/쓰기는 `try/catch`로 감싼다. 저장소를 쓸 수 없는 환경(시크릿 모드 등)에서는 메모리 상태로만 동작하고 안내 문구를 표시한다.
- 파싱 실패 시 빈 목록으로 시작하고 원본은 덮어쓰지 않는다.

### 6.3 날짜 처리
- "오늘"은 사용자 로컬 타임존 기준 `YYYY-MM-DD`.
- 기본 화면에는 `date === 오늘`인 항목만 표시. 지난 날짜는 F-15 기록 보기에서 표시.
- 페이지 로드 시 `lastDate !== 오늘`이면 F-12 이월 흐름(4.4) 실행.

### 6.4 기록 보관 정책
- 지난 날짜 항목은 자동으로 삭제하지 않는다.
- 사용자가 직접 삭제(× 버튼, F-14)한 항목만 저장소에서 제거한다.
- 용량 추정: 항목 1개 약 200바이트, localStorage 한도 약 5MB → 약 2만 개 이상 보관 가능(하루 10개 기준 5년 이상).
- 저장 실패(용량 초과) 시 경고를 표시하고, P2의 JSON 내보내기로 백업하도록 안내한다.

## 7. 기술 설계

### 7.1 기술 스택
- **HTML + CSS + Vanilla JavaScript** (빌드 도구·프레임워크 없음)
- 이유: 기능 규모가 작고, 파일을 브라우저로 열기만 하면 실행되도록 하기 위함

### 7.2 파일 구조 (예정)

```
todolist/
├── prd.md          # 본 문서
├── index.html      # 마크업
├── style.css       # 스타일 (CSS 변수 기반 테마)
└── app.js          # 상태 관리·렌더링·저장
```

### 7.3 모듈 구성 (app.js)

| 모듈 | 책임 |
|---|---|
| `storage` | localStorage 읽기/쓰기, 예외 처리, 버전 관리 |
| `state` | todos 배열, 현재 필터·보는 날짜, 상태 변경 함수(add/toggle/edit/remove/setPriority/clearCompleted/carryOver) |
| `render` | 상태 → DOM 렌더링 (목록·정렬, 진행률, 빈 상태, 필터 탭, 이월 확인 창) |
| `events` | 이벤트 위임으로 입력·클릭·키보드 처리 |
| `date` | 오늘 날짜 계산, 표시 포맷, 이월 판단 |

- 데이터 흐름: **이벤트 → state 변경 → storage 저장 → render** (단방향)
- 목록 클릭 이벤트는 `<ul>`에 위임해 항목별 리스너를 만들지 않는다.
- 사용자 입력은 `textContent`로만 렌더링해 XSS를 방지한다(`innerHTML` 사용 금지).

## 8. 비기능 요구사항

| 항목 | 기준 |

## 9. 엣지 케이스

- 공백만 입력 → 추가하지 않음
- 100자 초과 입력 → 입력창에서 제한(`maxlength`)
- localStorage 용량 초과/차단 → 메모리 모드로 동작, 경고 표시
- 저장 데이터 손상(JSON 파싱 오류) → 빈 목록으로 시작
- 자정을 넘겨 페이지를 계속 열어둔 경우 → 포커스 복귀(`visibilitychange`) 시 날짜 재확인
- 여러 탭에서 동시 사용 → `storage` 이벤트로 다른 탭 변경 사항 반영. 이월 확인 창은 한 탭에서 처리되면 다른 탭에서는 닫는다(`lastDate` 변경 감지)
- 이월 확인 창에서 모든 항목 선택 해제 후 [가져오기] → 건너뛰기와 동일하게 처리
- 이월된 항목을 다음 날에도 끝내지 못함 → 다음 날 다시 이월 확인 대상이 됨
